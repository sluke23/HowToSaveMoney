# IRR 算法与输入格式

作者：毛毛&luke。新增计算说明与示例，CC BY-NC-SA 4.0。计算器使用 Python 3.9+ 标准库，无需联网或金融库。

## 统一比较口径

借款人视角，流入为正，支付为负；同一期或同一天合并。有效年化 R 满足 `Σ[C_k÷(1＋R)^t_k]＝0`，t_k 用年表示。

- 等间隔 periodic：每年 m 期，期号 k 从 0 起，`t_k＝k/m`。求得有效年化 R 后，每期 IRR `r＝(1＋R)^(1/m)−1`；名义年化 `m×r`。月度 m＝12，日度 m＝365，周度按所声明的周期约定。月度等间隔模型不等于每月都实际 30 天。
- 实际日期 dated：`t_k＝(d_k−d_0).days÷365`，含闰年实际天数，分母固定 365，给年度 XIRR。它已经是有效年化，不再乘 12；不能把换算的月等效值称为实际月 IRR。

同一比较表优先统一日期或周期约定，不能把一个方案的“月 IRR×12”和另一个的有效年化排在同列。输入日期及费用缺失时标注假设。上述为数学比较口径，法律披露、计息基准和司法认定另查。

## 等间隔输入

```json
{
  "mode": "periodic",
  "periods_per_year": 12,
  "cashflows": [10000, -893.33, -893.33, -893.33, -893.33, -893.33, -893.33, -893.33, -893.33, -893.33, -893.33, -893.33, -893.37]
}
```

`cashflows[0]` 是初始净到账，以后每个元素占一期，没收付的中间期填 0，末期之后不加无意义的 0。实际首期提前或延期时改用日期，不把首期强行挪到一个月末。`periods_per_year` 必填正数，不能省略后默认月度。

## 实际日期输入

```json
{
  "mode": "dated",
  "cashflows": [
    {"date": "2026-11-16", "amount": 10000, "label": "放款"},
    {"date": "2026-11-16", "amount": -300, "label": "强制服务费"},
    {"date": "2026-12-16", "amount": -1000},
    {"date": "2027-02-16", "amount": -9500}
  ]
}
```

日期为 `YYYY-MM-DD`，可乱序提交，脚本会排序、同日净额合并；可选 `label` 便于输入审阅，不参与计算。金额为有限数字，收付方向以正负表示。仅接受这两种 schema；未知字段、日期错误、布尔值冒充数字等会报错，避免错拼字段后费用被静默忽略。

日期案例的 300 元已经在同日净额中扣除，不再另减一次。币种由助手和用户统一，脚本不做汇兑；输入一个方案的同币种现金流，不把不同产品拼成一个利率。

## 执行与解释结果

将输入保存为用户指定或临时目录的 UTF-8 JSON；从任意工作目录执行：

```bash
python3 "<skill目录>/scripts/loan_irr.py" --input /path/to/loan.json
```

脚本向标准输出给 JSON，不修改合同或账户。无效输入向标准错误报错并以状态码 2 退出。主要字段：

| 字段 | 意义 |
| --- | --- |
| `effective_annual_irr_percent` | 主比较值：有效年化 IRR，dated 时即 ACT/365F 的 XIRR |
| `periodic_irr_percent` | periodic 的每期 IRR；dated 为 null |
| `nominal_annual_percent` | periodic 的每期 IRR×每年期数；dated 为 null |
| `net_inflows` / `net_outflows` | 同期/同日先净额合并，再分别加总的流入与流出，不代表合同名义本金 |
| `net_financing_cost` | 净流出−净流入，包含所录入的强制费用；不是只按合同科目定义的“利息” |
| `peak_net_outflow` | 最大一期/一天净流出；用于理解付款压力，不能把单日值当每月月供 |
| `cashflows` | 排序且合并后的收付序列，用于复核费用与日期 |
| `relative_npv_residual` | 根求解的相对残差；验证算法，不证明输入完整或合同合法 |

所有以 `_percent` 结尾的结果已乘 100，比如 13.84 表示 13.84%，不要再次乘 100。通常向用户展示到小数点后两位，并附关键现金流和口径，不倾倒 JSON 或把算法残差当成广告可信度。

## 求解与限制

脚本在 `y＝ln(1＋R)` 空间使用稳定的对数求和与二分求根。对合并后“先净流入、后净流出”，且只有一次正转负的现金流，存在唯一大于 −100% 的常规 IRR。可处理多笔前置放款、零利率及负融资成本；负值只说明该输入下的现金流，不代表该贷款可套利。

如果同日全部收付后没有融资期、只有一种符号，或正负反复出现，脚本会拒绝。多次变号可能无解、多解或仍有唯一解，这个计算器不作全根判别，不任取一个根。保留完整现金流，说明限制；可按需要用已核验的其他方法找全部相关根，或改用明确折现率下的净现值及逐期现金预算。不能删返现、二次放款或移日期以强行通过校验。

极端输入导致求解结果超出浮点表示范围时会报错；百分比四舍五入显示为 −100% 不代表合法利率可取该值。未知未来费率、循环支用、逾期和部分提前还款只按已明确的情景计算，不作未来成本保证。
